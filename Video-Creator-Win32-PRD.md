# Video Creator for Windows 98 and XP

**Product requirements and implementation brief for Codex CLI**

Deliver Almathera’s Amiga CD32 *Video Creator* as a native, 32-bit x86 Windows application. A user can unzip a release on a period PC, open the editor, build a music-synchronized visual sequence, save it, close the application, reopen the sequence and play it back. The release runs offline without an Amiga emulator, ROM, AmigaOS libraries, translated 68020 code at runtime, or developer tools.

The work has two parts. Port the original application logic and hardware-dependent routines to portable C and Win32. Then cross-compile that source on a modern machine. The project is finished when the same release passes the user workflows on both Windows families. An editor window or a playing demo is an intermediate milestone.

## Product scope and platform decisions

**Who and what to support.** The primary user is a Video Creator owner working on a Windows 98 or XP PC. Preserve the original editing sequence, effect parameters, file compatibility and timing. The editor, player and import path must work with a mouse and keyboard. Map original controller actions to usable PC controls and preserve the controller-only workflow where the original supports it. Include the source’s reachable language choices and preferences. The initial engineering work should target a single portable release ZIP containing `VCEDIT.EXE` plus its required data.

**Target matrix.** Build one x86 PE32 GUI executable for both Windows families. Target Windows 98 First Edition, Windows 98 Second Edition and 32-bit XP, checking XP RTM and SP3 to bracket the family. Test on clean, stock installations and publish the exact editions tested. Exercise the same checksummed package on at least one physical Windows 98 PC and one physical XP PC before claiming native hardware validation for both. A VM running a real target OS is useful for additional edition coverage. A modern Windows or Wine smoke run is development evidence only. Record CPU, RAM, graphics mode, sound and optical hardware for each run. Start with baseline x86 code without mandatory SSE/SSE2 and set the published hardware minimum from measurements.

**Build decision.** Try a pinned Open Watcom v2 host toolchain first. Use a modern Linux/WSL host or the modern Windows host if that is the available Codex environment. Start with its 32-bit C compiler (`wcc386 -bt=nt`), Win32 headers and `wlink` GUI PE profile (`system nt_win`). Inspect the resulting OS/subsystem version and imports before running it on the target. Capture compiler, linker, startup objects, library versions, command lines and checksums. If the chosen snapshot fails on 98, diagnose imports/startup requirements before changing compilers. An independently pinned Win9x-compatible x86 MinGW toolchain is a fallback. Qualify each candidate with the same probe. [Open Watcom releases](https://github.com/open-watcom/open-watcom-v2/releases) · [Compiler guide](https://open-watcom.github.io/open-watcom-v2-wikidocs/cguide.html) · [Linker guide](https://open-watcom.github.io/open-watcom-v2-wikidocs/lguide.html)

**Feature boundary.** Account for every reachable feature of the archived editor, including conditional device paths. The full release includes working equivalents for reachable optional hardware functions when appropriate media or hardware is present. Publish a capability matrix for absent, unsupported and available devices. Missing original assets, unverified behavior and intentionally unimplemented historical features are distinct statuses. An unresolved required behavior keeps the corresponding milestone open. New video export formats, an online service and UI redesign are outside this port.

## Native implementation and acceptance

| Area | Required behavior and test |
|---|---|
| Projects and media paths | Use explicit file parsers, bounded values and stable object IDs. Preserve effect order, parameters, timing, strings, referenced assets and named volume paths across open → save → reopen. Resolve `VCPics:`, `VCQuads:`, `VCVecAnims:`, `VC3D:`, `VCVideos:` and source-relative paths through a case-insensitive asset catalog. Keep Windows absolute paths out of exported legacy projects. Exercise spaces, missing files, failed saves and interrupted replacement on a FAT-compatible filesystem. A bad import or save must preserve the previous project. |
| Pictures and UI assets | Read pictures and thumbnails by content, including IFF ILBM with numeric extensions and `.tn`. Implement the used chunks, row padding, compression, bitplane order, palettes and original centering/scaling. Inventory Amiga datatype-dependent import formats and implement or explicitly resolve each supported family. Handle `.vcdir` catalogs and missing thumbnails without losing usable pictures. |
| Renderer and effects | Start with a CPU renderer, indexed pixels and palette state, then present the result through a Win32 GDI DIB. Model per-scanline changes, masks, bitplane operations and fixed-width arithmetic wherever visible. Preserve original effect limitations, including the straight-cut fallback for a crossfade between incompatible screens. Track each effect’s source symbol, defaults, legal input, fallback, reference frame and native test. |
| Special screens and audio | Implement 2D vectors, 3D objects, QuadAnims and text layout/scrolling from the original routines. Test fixed-point signs, clipping, frame sequence, speed, palette changes and composition with transitions. Map reachable sample playback to native PCM output and test the original sample/trigger behavior. Identify which bundled 8SVX samples are actually reachable. Do the same for any tracker-module references before assigning them to the release. |
| CD and playback clock | Provide a native CD-DA transport, starting with WinMM/MCI. Support the original track selection, track boundaries, TOC, play/stop, seek where used, disc-change handling and no-drive operation. Trace the optional `cd32mpeg.device` path and verify its actual track/display behavior with appropriate media. Use a deterministic test transport with a PCM WAV fixture for machines without optical drives. If exposed in the editor as a drive-free convenience, store the local audio mapping separately from the legacy project. [Microsoft CD audio commands](https://learn.microsoft.com/en-us/windows/win32/multimedia/cd-audio-command-set) |
| Editor workflow | Match the reference layout and interactions well enough to follow the bundled manual with PC controls. Cover thumbnails, effect selection and parameters, timeline drags and ordering, block operations, Listen/mark, playback, preferences, load/save and Random Raves. Preserve repeatable behavior for a known random seed. Exercise focus loss, window repaint, playback stop and closing with unsaved work. |
| Native runtime and delivery | Keep host tools, parsers used only for tests and asset preparation off the target PC. Inspect PE headers, CPU instructions from the chosen build baseline, subsystem version and imported DLLs/functions including transitive dependencies. Test ANSI Win32 entry points on the Windows 98 floor. Record any optional APIs resolved at runtime and test their fallback. The end user can launch the release offline from a writable directory using Explorer. [Microsoft PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) |

**Implementation structure.** Keep the timeline, project format, asset decoding, palette state and effect math in portable C so tests can run on the modern host. Put windows, DIB presentation, input, files, timers and audio devices behind narrow Win32 interfaces. For every original linked module, record which functions were reused, adapted or behaviorally replaced and where the tests live. Read big-endian fields explicitly, check widths and alignment, and replace pointer-valued effect parameters with typed IDs at the serialization boundary. A reconstructed lookup table needs an independent check of its scale, wrap point and rounding before it becomes a reference.

## Reference tests Codex can start with

**An independent first-frame check.** In the pinned ZIP, `vc/data/blankeditor.iff` is a 320 × 256 ILBM with seven planes, a 128-entry palette and ByteRun1-compressed body. Decode to top-to-bottom, left-to-right RGB24, exactly three bytes per pixel in R,G,B order. Hash the raw pixels before window scaling, row reversal or display color conversion. A direct planar decode and FFmpeg independently produced identical bytes during preparation of this brief.

| Fixture output | Exact expected value |
|---|---|
| Input file SHA-256 | `bd76f69411a1b4eca339edc1651226d12d3c76ee76172d0d1950d2959480c86a` |
| Raw RGB output length | 245,760 bytes |
| Raw RGB output SHA-256 | `268d851d1941790a3019c94c3a3b8319259246680808b969b8d768923fa3b9bf` |

**Project compatibility.** Create a minimal VC10 fixture by following `SaveVideo` byte for byte, including the single-byte header encoding, author and track lines, shifted name/text bytes, `ZIP` and `NOTEXT` sentinels and screen/object numbering. Test both an ordinary picture and a two-picture screen. Confirm the original reader accepts Windows output using the archived editor on reference hardware or an optional development-only Amiga emulator if available. Label synthetic fixtures, source-derived expectations and independent reference captures separately. Test the older-looking `defvid` against its own grammar and missing references. Never manufacture a successful historical load by silently discarding fields.

**Timing.** For CD audio, sector offsets 0, 2, 3 and 75 map to timeline ticks 0, 0, 1 and 25. Test start at a nonzero track offset, repeated seek, simultaneous cues, stop/restart and long playback. A proposed release target on each declared hardware baseline is a representative ten-minute sequence with cue error within one 40 ms timeline tick, measured against audio position after startup, and no accumulating drift. Record the largest observed error, missed cues, test media and machine. Verify any separate field-rate behavior in rendering with source or reference captures.

**Effects.** One small sequence should combine a straight cut, a palette cycle, a vector or QuadAnim and a text change. Compare the frames before, at and after each event. For integer rendering and deterministic fixtures, require exact canonical pixel or palette matches. Use an explicit tolerance and explain any conversions for analog captures, fonts or recordings. Keep capture provenance. A port-generated screenshot alone can verify a regression only after its expected behavior has independent support.

**User test on each Windows family.** Unzip to a path with a space. Launch using Explorer. In a fresh project, load two images, a special screen and an audio source. Add and reorder effects, mark one cue while listening, preview, save, exit, reopen and play to the end. Repeat with no optical drive or disc and check the documented behavior. Exercise a real audio disc where available. Capture the app version and hash, OS/build, relevant hardware, project and result. Repeat open/play/stop/close cycles and check memory, GDI resources and audio-device release on the target. A working second launch is part of the test.

## Release contract and handoff

Make the repository expose one documented command each to bootstrap the pinned tools, build x86 release, run host tests, inspect PE/imports and assemble the portable ZIP. Add a Windows 98-compatible way to run the target smoke test by double-click or from `COMMAND.COM`; keep PowerShell and Python on the development host. Provide exact commands in the repository README once they actually work. Preserve source/archive provenance and document any outside input required to reproduce a build.

The user receives the port source, the portable release or clearly labeled candidate, a list of supported functions and tested targets, and a short guide for using original assets and audio. A developer can rebuild from scratch and reproduce the fixture checks. If an original demo, font or MPEG test disc remains unavailable, say which operation it prevents verifying and which replacement or user-provided file can resolve it. Keep that uncertainty visible through release.

**First meaningful demo.** On a Windows 98 PC, open the real editor artwork, add two pictures and a timed transition, save the project, then play that same file on XP with the same executable.
